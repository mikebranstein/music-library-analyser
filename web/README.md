# Music Library — static site (`web/`)

A zero-build, offline, browsable view of the whole analysis pipeline. It opens by
**double-clicking `index.html`** — no server, no `npm`, no build step. Everything is plain
HTML/CSS/JS, and data is delivered as generated `.js` files (classic `<script>` tags), so it
works from the `file://` protocol without `fetch()` or ES modules.

> **Data is never source-controlled.** Real runs derive from copyrighted sheet music, so
> nothing under `web/data/` is committed. A fully **made-up** sample lives in
> `web/data-sample/` (committed). Copy it into `web/data/` to preview the scaffold:
>
> ```powershell
> .\.venv\Scripts\python.exe web\seed_sample.py
> ```
>
> On a fresh clone with an empty `web/data/`, the site shows a friendly “run Script 09”
> notice instead of crashing.

## Open it

- **Simplest:** double-click `web/index.html`.
- **Optional local server** (if you prefer an `http://localhost` origin):
  ```powershell
  .\.venv\Scripts\python.exe web\serve.py
  ```
  then visit http://localhost:8000/.

## What's hand-authored vs. generated

| Path | Committed? | Author |
| --- | --- | --- |
| `index.html`, `pages/*.html` | yes | hand-authored scaffold |
| `css/*.css`, `js/*.js` | yes | hand-authored scaffold |
| `serve.py`, `seed_sample.py`, this `README.md` | yes | hand-authored scaffold |
| `data-sample/*.js` | yes | fully made-up preview fixture |
| `data/*.js` | **never** (git-ignored) | written by `09_static_site.py` (or seeded from the sample) |
| `assets/thumbs/*.webp` | git-ignored | generated by Script 09 (Pillow) |
| `assets/pdfs/*` | git-ignored | only when run with `--copy-pdfs` |

The `data-sample/*.js` files are a **small, entirely fictional** fixture so the scaffold can
be previewed without real data. Nothing derived from actual music is ever committed.

## Regenerate the data

```powershell
.\.venv\Scripts\python.exe scripts\09_static_site.py --library-root "C:\Temp\NSCB"
```

## Structure

```
web/
  index.html              Dashboard (overview + drill-down)
  pages/
    phase-01-ingest.html … phase-08-review.html   one page per pipeline phase
    pieces.html  piece.html                        piece index + detail
    documents.html  document.html                  document index + detail
    page.html                                       deepest page detail
  css/  theme.css  layout.css  components.css       design tokens + layout + components
  js/   core.js        MLG namespace, chrome, theme, settings, search, PDF links
        render.js      shared presentational helpers
        tables.js      sortable + filterable data tables
        charts.js      dependency-free inline-SVG / bar charts
        dashboard.js   dashboard renderer
        phase.js       generic phase-page renderer (data-driven)
        entities.js    pieces / piece / documents / document / page renderers
  data-sample/ 00_manifest.js … 50_pages.js          committed made-up preview fixture
  data/        (git-ignored)                          real/seeded data lives here
  assets/ thumbs/  pdfs/ (generated, git-ignored)
  serve.py  seed_sample.py
```

## Design

The visual language follows [`../docs/WEB_DESIGN_REFERENCE.md`](../docs/WEB_DESIGN_REFERENCE.md)
— a "paper & ink" light theme and a "stage light" dark theme, a single brass accent, borders
over shadows, and flat fills. Toggle light/dark from the header; the choice is stored in
`localStorage`.

## Linking to the original PDFs

Documents store a `pdf_path` **relative** to your music library. Because the library lives
outside the repo, the site composes absolute `file://` links **at click time** from a
**Library location** you set via the header ⚙ settings (persisted in `localStorage`). If the
`web/` folder or the library moves, update that one field and every PDF link keeps working. The
resolved absolute path is also shown as copyable text.
